# 高校学科竞赛辅助服务智能体系统

面向高校学院（计算与智能技术学院）的学科竞赛全流程辅助系统。覆盖赛事知识问答、通用模型问答、竞赛推荐、备赛辅助、项目指导、预算/借款/报销辅助、参赛与获奖统计、可视化分析及结果导出。

系统默认使用**内置离线智能体**，不需要任何大模型密钥即可完整运行；同时保留 DeepSeek、通义千问（Qwen）、豆包（Doubao）及任意 OpenAI 兼容端点的接入配置。重要政策、时间节点与统计数据均以知识库原文和结构化台账为准，不依赖大模型生成。**通用模型问答**面向全部身份开放，可自主选择已配置的模型；该页不读取台账、不生成引用，不作为竞赛业务事实的依据。

## 1. 功能一览

| 模块 | 能力 | 主要实现 |
| --- | --- | --- |
| 竞赛知识问答 | 通知、规程、资格、截止时间、材料、奖项问答，逐条标注原文片段与章节 | RAG 混合检索 + LangGraph 6 节点工作流 |
| 通用模型问答 | 所有身份可用的通用对话；用户可自主切换服务端已配置的 DeepSeek / 通义 / 豆包 / 自定义端点 | 模型目录 + 服务端密钥 + 通用对话接口（不读取台账） |
| 竞赛推荐 | 按专业、年级、技术方向、项目基础、意向级别计算适配度并排序 | 适配度规则表 + 4 节点工作流 |
| 备赛辅助 | 自动倒排备赛阶段、任务清单、材料要求与提醒 | 届次时间节点 + 知识库规程检索 |
| 项目指导辅助 | 申报书/作品说明章节完整性、要素覆盖、规范性初检，生成修改建议与预答辩问题 | 量表规则 + 可选大模型增强 |
| 预算申请辅助 | 按费用标准测算报名、交通、住宿、补助等明细，生成预算申请正文与审批路径 | 费用标准表 + 规则引擎 |
| 借款辅助 | 基于已批准预算生成借款单，金额大写、预算关联与事前校验 | 财务规则 + 单据生成 |
| 报销辅助 | 逐项核对票据、超标、超预算、时限与材料完整性，生成报销单 | 财务规则 + 完整性评分 |
| 竞赛数据统计 | 年度、赛事、专业、获奖等级、赛事级别、教师、学生、工作量 8 个维度 | Pandas + 结构化台账 |
| 可视化分析 | 趋势、对比、占比、热力图等 ECharts 图表 | ECharts 5 |
| 结果导出 | 统计报表、获奖台账、参赛台账、知识清单、费用标准、规则、智能体结果与会话归档 | openpyxl / python-docx / CSV |

系统另有赛事台账维护、参赛与获奖台账、知识库管理、智能体工作流总览、运行日志与导出中心等管理页面。

所有页面与接口按**学生 / 教师 / 管理员**三种身份做权限分离：菜单、路由、操作按钮与后端接口使用同一套权限矩阵，越权请求由后端返回 403，不依赖前端隐藏。详见 [角色与权限](#7-角色与权限rbac)。

## 2. 技术架构

```
Vue 3 + Element Plus + ECharts  (frontend/dist，由 FastAPI 直接托管)
                       │  /api/*
FastAPI ── LangGraph（8 个 StateGraph）
   │           ├── 内置离线规则通道（默认）
   │           └── DeepSeek / Qwen / Doubao / OpenAI 兼容通道（可选）
   ├── 通用模型问答：服务端模型目录 + 多供应商密钥，所有身份可切换模型
   ├── RBAC：security.py 权限矩阵 + X-User-Role 请求头 + 会话级数据隔离
   ├── RAG：PDF/Word/Excel/Markdown/TXT/CSV/JSON 解析 → 分块 → 向量 + BM25 混合检索
   ├── Pandas 统计与 openpyxl / python-docx 导出
   └── SQLAlchemy 2.0
          ├── SQLite（默认，开箱即用）
          └── MySQL 8 / PostgreSQL 16（通过 DATABASE_URL 切换）
```

- **智能体编排**：`langgraph` 0.3.x，8 张状态图、32 个节点，节点与 `backend/prompts/*.yaml` 一一对应，启动时校验。
- **通用模型问答**：独立于 8 个智能体，不进入 LangGraph 工作流；模型目录只包含服务端预置的供应商，客户端只能提交模型 id，不能指定端点，API Key 不会返回前端。
- **知识库**：默认 512 维离线哈希向量 + jieba/BM25 混合检索，无需外部向量库；知识片段保留文档、章节、页码、行号与原文路径。
- **规则外置**：费用标准、审批阈值、推荐权重、获奖积分、材料检查量表均位于 `backend/data/rules/*.yaml`，导入数据库后生效，修改无需改代码。
- **数据外置**：赛事目录、届次、台账、主数据位于 `backend/data/seed/*.json`，可重复导入。
- **零配置运行**：未配置大模型或向量模型时，所有 8 个智能体走离线规则通道，工作流轨迹、结构化表格、图表与导出保持一致。

## 3. 快速启动（Windows）

前置条件：Python 3.11–3.13（已在 Python 3.13 验证）。运行期不需要 Node.js，前端已构建在 `frontend/dist`。

```bat
cd /d <项目目录>
start_windows.bat
```

脚本会自动完成：创建 `backend/.venv` → 安装依赖 → 首次运行时建库并导入演示数据与知识库 → 启动服务。

浏览器访问：

- 系统首页：<http://127.0.0.1:8000>
- 接口文档：<http://127.0.0.1:8000/api/docs>

也可手动启动：

```bat
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\init_db.py --seed
.venv\Scripts\python.exe scripts\ingest_knowledge.py
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### Linux / macOS

```bash
bash start.sh
```

或手动执行相同步骤，将 `.venv/Scripts/python.exe` 替换为 `.venv/bin/python`。

> 首次启动需安装依赖，且需下载 jieba 词典等资源，耗时约 1–3 分钟。之后启动为秒级。数据库已随交付包提供；删除 `backend/data/competition_agent.db` 可重新初始化演示数据。

### 前端开发模式（可选）

仅在需要修改 Vue 源码时使用，需要 Node.js 18+：

```bash
cd frontend
npm install
npm run dev          # http://127.0.0.1:5173，代理 /api 到 8000
npm run build        # 重新生成 dist，FastAPI 自动托管
```

## 4. 大模型配置（可选）

复制 `backend/.env.example` 为 `backend/.env`，按需修改：

| 变量 | 说明 |
| --- | --- |
| `LLM_PROVIDER` | `builtin`（默认）/ `deepseek` / `qwen` / `doubao` / `openai_compatible` |
| `LLM_API_KEY` | 对应平台密钥 |
| `LLM_BASE_URL` | 留空使用内置默认地址，自定义端点时填写 |
| `LLM_MODEL` | 留空使用内置默认模型，如 `deepseek-chat`、`qwen-plus`、`doubao-1-5-pro-32k` |
| `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `DOUBAO_API_KEY` | 通用模型问答中各家模型的独立密钥；可同时配置多家，未配置的模型在前端显示为「未配置」并禁用 |
| `DEEPSEEK_MODEL` / `QWEN_MODEL` / `DOUBAO_MODEL` | 可选，覆盖通用问答中对应供应商的模型名 |
| `LLM_CHAT_MAX_MESSAGES` / `LLM_CHAT_MAX_CHARS` | 通用问答上下文上限，默认 20 条 / 16000 字符 |
| `EMBEDDING_PROVIDER` | `builtin`（默认）/ `qwen` / `doubao` |
| `EMBEDDING_DIM` | 与所选向量模型一致；切换后需重建知识索引 |

通用模型问答的密钥规则：

- 密钥只在后端读取，`GET /api/llm/models` 只返回模型名、可用状态与缺失原因，不返回 `base_url` 或 API Key。
- 当前主通道（`LLM_PROVIDER` 对应供应商）可以复用 `LLM_API_KEY`；其他供应商需使用各自的 `*_API_KEY`，避免把一家的密钥发送到另一家端点。
- 只配置通用问答密钥、保持 `LLM_PROVIDER=builtin` 时，8 个业务智能体仍走离线规则通道，通用问答可单独使用云端模型。

切换数据库示例：

```env
DATABASE_URL=mysql+pymysql://user:password@127.0.0.1:3306/competition_agent?charset=utf8mb4
# 或
DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/competition_agent
```

切换数据库或向量模型后，重新执行 `init_db.py --seed` 与 `ingest_knowledge.py`。完整说明见 [部署与使用手册](docs/01-部署与使用手册.md)。

## 7. 角色与权限（RBAC）

系统内置三种身份。页面右上角（移动端为侧边菜单底部）的身份选择器用于演示，切换后菜单、路由与接口权限同步变化。前端在每次 API 请求中携带 `X-User-Role: student|teacher|admin`，后端 `app/security.py` 统一校验；请求体中的 `user_role` 不作为授权依据，角色一律以请求头为准。

| 能力 | 学生 | 教师 | 管理员 |
| --- | :---: | :---: | :---: |
| 工作台、知识问答、竞赛推荐、备赛辅助、项目指导 | ✓ | ✓ | ✓ |
| 通用模型问答（自主选择已配置模型） | ✓ | ✓ | ✓ |
| 统计分析与赛事台账查看 | ✓ | ✓ | ✓ |
| 单次智能体结果导出（Word / Excel） | ✓ | ✓ | ✓ |
| 参赛与获奖台账、批量报表导出 | — | ✓ | ✓ |
| 经费预算 / 借款 / 报销编制与提交 | — | ✓ | ✓ |
| 经费审批、驳回、放款与冲销 | — | — | ✓ |
| 知识库查看与检索 | — | ✓ | ✓ |
| 知识库上传、同步、重建索引、删除 | — | — | ✓ |
| 赛事台账新增、年度收录、编辑、删除 | — | — | ✓ |
| 智能体工作流总览、运行日志 | — | ✓（日志） | ✓ |

- **接口级强制**：未授权请求返回 `403`；未知身份返回 `400`。智能体列表接口只返回当前身份可用的智能体。
- **数据隔离**：问答会话按身份隔离，学生与教师不能读取、删除对方的会话；管理员可查看全部会话。
- **通用问答边界**：`llm.use` 对所有身份开放，模型目录由服务端限定；该页对话不写入业务台账，不检索知识库，也不作为政策、时间、金额与统计数据的依据。
- **前端一致**：`auth.js` 保存与后端相同的权限矩阵，导航、路由守卫与审批按钮据此渲染；隐藏按钮只是体验优化，安全边界仍在后端。
- **正式部署**：当前为应用层角色控制，不含账号密码登录。接入学校统一身份认证（CAS / OAuth2 / 反向代理）后，应由认证层注入可信角色，移除前端的演示身份切换，并禁止客户端自行提交角色请求头。详见 [部署与使用手册](docs/01-部署与使用手册.md#6-角色权限与安全)。

## 10. 说明与边界

- 本系统为学院内部辅助工具，当前提供基于角色请求头的应用级权限控制，**不含账号密码登录**。部署到校园网时应在反向代理或网关层接入统一身份认证，由认证层写入可信角色并移除客户端角色切换，同时收紧 `CORS_ORIGINS`。
- 知识库回答严格基于已导入文件；文件未覆盖的内容会明确提示补充资料，不做无依据推测。
- 统计数字来自参赛与获奖台账；演示数据仅用于功能验证，不代表任何真实学院的竞赛成绩。
- 通用模型问答由所选大模型直接生成，不检索知识库、不读取台账，不提供引用；涉及竞赛政策、时间、费用与统计的问题，应使用竞赛知识问答或对应业务页面。默认未配置任何云端密钥时，该页会展示配置指引并禁用发送。
- 通用问答目前不持久化对话，也没有按用户计费/配额；正式开放到公网前，建议在网关层增加登录、限流与额度控制。
- 离线通道保证可用性与数据一致性；接入大模型后可提升自然语言理解与表达质量，但不会改变金额、排名、获奖率等由规则和台账计算的字段。

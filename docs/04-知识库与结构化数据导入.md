# 知识库与结构化数据导入

本系统有两类数据来源，职责严格区分：

| 类型 | 内容 | 用途 | 存放位置 |
| --- | --- | --- | --- |
| 知识库（非结构化） | 竞赛通知、规程、管理办法、获奖名单、评审标准 | 问答、备赛材料、经费制度引用，必须带原文出处 | `backend/data/knowledge` 或上传目录 |
| 结构化数据 | 赛事、届次、赛道、时间节点、参赛、获奖、成员、规则 | 推荐、备赛倒排、统计、经费计算、导出 | `backend/data/seed`、`backend/data/rules`、数据库 |

新增赛事、政策文件或年度数据均不需要修改代码。

## 1. 知识库支持格式

| 格式 | 解析方式 | 溯源定位 |
| --- | --- | --- |
| `.pdf` | pypdf 提取文本 | 页码 |
| `.docx` | python-docx 提取段落与表格 | 章节路径 |
| `.doc` | 按 docx 尝试解析 | 建议先另存为 `.docx`，旧版二进制 `.doc` 可能解析失败 |
| `.xlsx` / `.xls` | openpyxl 读取工作表 | 工作表 + 行号 |
| `.csv` | 按行解析 | 行号 |
| `.md` / `.markdown` | 按标题层级解析，支持 YAML front matter | 标题路径（如 `通知 > 四、报名安排`） |
| `.txt` | 按自然段与章节切分 | 文本段落 |
| `.json` | 递归展开键值 | 键路径 |

限制：单文件 ≤ 50 MB；扫描版 PDF 没有文本层，需先 OCR；加密文档需先解除密码。

## 2. 元数据规范

推荐在 Markdown 文件顶部写 YAML front matter，系统会自动读取；其他格式可在上传时填写。

```markdown
---
title: 关于举办第十七届蓝桥杯全国软件和信息技术专业人才大赛的通知
doc_type: 通知公告
year: 2026
competition_name: 蓝桥杯全国软件和信息技术专业人才大赛
issuing_body: 蓝桥杯大赛组委会
doc_no: 蓝桥杯组委〔2025〕6号
effective_date: 2025-10-08
source_url: https://dasai.lanqiao.cn/
tags: [蓝桥杯, 报名, 省赛, 国赛, 材料]
---

# 关于举办……的通知

## 一、赛事组织
...
```

字段说明：

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `title` | 文本 | 文档标题；缺省使用文件名 |
| `doc_type` | 通知公告 / 竞赛规程 / 管理制度 / 获奖名单 / 评审标准 / 其他 | 分类筛选与问答提示 |
| `year` | 整数 | 年度筛选；问答按年份限定检索 |
| `competition_name` | 赛事全称或简称 | 自动关联赛事；影响按赛事限定检索 |
| `competition_id` | 整数（可选） | 直接指定关联赛事 |
| `issuing_body` | 发文单位 | 引用展示 |
| `doc_no` | 文号 | 引用展示与审计 |
| `effective_date` | `YYYY-MM-DD` | 制度生效日期 |
| `source_url` | URL | 「官方来源」链接 |
| `tags` | 字符串数组 | 标签检索与展示 |

未提供元数据时，系统会尝试从文件名推断年度（如 `2026-蓝桥杯-...`）、从标题关键词推断文档类型，并按标题匹配赛事。推断结果可在入库后通过重新上传或直接修改 `kb_documents` 校正。

## 3. 导入方式

### 3.1 页面上传（推荐给业务人员）

1. 进入「知识库」页，点击「上传文档」。
2. 选择文件，填写文档类型、年度、关联赛事、发文单位、文号、原文链接、标签。
3. 点击「解析并入库」，系统解析、分块、向量化并立即更新索引。
4. 在文档目录查看片段数、字数、状态；失败时显示原因，可「重建」重试。

### 3.2 批量导入目录（推荐给管理员）

将文件放入 `backend/data/knowledge`，执行：

```bash
cd backend
python scripts/ingest_knowledge.py
```

参数：

| 参数 | 说明 |
| --- | --- |
| `--dir <目录>` | 指定导入目录，默认 `data/knowledge` |
| `--file <文件>` | 只导入指定文件，可重复 |
| `--no-replace` | 相同内容（文件哈希一致）时跳过；默认会替换旧版本 |
| `--no-init` | 跳过建表检查（数据库已初始化时） |

脚本会输出每份文档的状态、分块数、字符数，并重建内存索引。

### 3.3 页面「同步目录」

扫描 `data/knowledge` 并增量导入。文件内容变化（哈希不同）会替换旧文档与片段；未变化则跳过。适合学院按学期批量投放通知后一键更新。

### 3.4 通过接口上传

```bash
curl -X POST http://127.0.0.1:8000/api/knowledge/upload \
  -F "file=@2027-蓝桥杯-报名通知.pdf" \
  -F "doc_type=通知公告" \
  -F "year=2027" \
  -F "competition_id=1" \
  -F "issuing_body=蓝桥杯大赛组委会" \
  -F "doc_no=蓝桥杯组委〔2026〕x号" \
  -F "source_url=https://dasai.lanqiao.cn/" \
  -F "tags=报名,省赛"
```

文件保存在 `data/uploads/`（重名自动加时间戳），元数据写入 `kb_documents`。

## 4. 解析、分块与检索

### 4.1 分块

- 优先按文档自身章节切分（Markdown 标题、Word 标题、Excel 工作表/行）。
- 单节超过 `RAG_CHUNK_SIZE`（默认 600 字）时按句子贪心装箱，窗口间保留 `RAG_CHUNK_OVERLAP`（默认 100 字）重叠。
- 每块记录 `section`（章节路径）、`page_no`（PDF 页码）、`row_ref`（Excel 行）、`char_count` 与分词缓存。
- 少于 30 字且非首块的碎片会与上下文合并或丢弃，避免无意义片段。

### 4.2 混合检索

```
查询 → 分词 → 向量余弦（离线哈希向量或云端 embedding）
             + BM25 关键词得分
             + 规则加权（关键词原样命中、年份一致、标题命中、条款编号命中）
     → 归一化加权 → 过滤最低分 → 取 Top K
```

默认 `向量 0.6 + 关键词 0.4`，最终返回 6 个片段（`RAG_TOP_K`），候选召回 20 个（`RAG_RECALL_K`）。问答工作流会在识别到赛事/年份时增加过滤条件；若范围内片段不足，会回退全库检索并在轨迹中注明。

### 4.3 引用溯源

每个片段生成引用对象：

```json
{
  "index": 1,
  "document_id": 4,
  "chunk_id": 37,
  "title": "关于举办第十七届蓝桥杯全国软件和信息技术专业人才大赛的通知",
  "doc_type": "通知公告",
  "doc_no": "蓝桥杯组委〔2025〕6号",
  "issuing_body": "蓝桥杯大赛组委会",
  "location": "关于举办……的通知 > 四、报名安排",
  "snippet": "报名时间：2025 年 10 月 8 日至 2026 年 3 月 20 日……",
  "score": 0.833,
  "source_path": "C:\\...\\data\\knowledge\\2026-蓝桥杯-大赛通知与参赛规程.md",
  "source_url": "https://dasai.lanqiao.cn/"
}
```

前端「参考资料」显示标题、文号、章节、相关度与原始文件下载按钮；Word/Markdown 导出保留 `[^n]` 编号与章节位置。引用的文件字段只显示文件名，完整路径保留在接口与数据库中。

### 4.4 索引重建与删除

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| 单文档重建 | 「知识库」文档行「重建」或 `POST /api/knowledge/documents/{id}/reindex` | 重新解析原文件、重算分块与向量 |
| 全量重建 | `POST /api/knowledge/reindex` 或重新执行导入脚本 | 用于切换 embedding 模型或调整分块参数 |
| 删除文档 | 页面「删除」或 `DELETE /api/knowledge/documents/{id}` | 级联删除片段，内存索引同步刷新 |
| 检索测试 | 页面检索框或 `GET /api/knowledge/search?q=...&top_k=6` | 不调用大模型，直接查看混合检索结果 |

切换 `EMBEDDING_PROVIDER` / `EMBEDDING_MODEL` / `EMBEDDING_DIM` 后必须全量重建，否则维度不一致会导致检索失败。

## 5. 新增赛事与年度数据

### 5.1 通过页面维护（推荐）

「赛事台账」→「新增赛事」填写赛事基础信息；保存后在详情中「新增年度」或「编辑年度」，录入：

- 年度、届次名称、状态（筹备中/进行中/往届）
- 通知标题、文号、发文单位、发布日期
- 报名开始/截止、比赛时间
- 参赛资格、队伍人数、指导教师上限
- 报名费、费用说明、所需材料
- 时间节点、赛道、奖项设置

保存后，知识问答、竞赛推荐、备赛计划、统计与导出会立即使用新数据，无需重启。

### 5.5 调整规则

| 规则 | 文件 | 生效方式 |
| --- | --- | --- |
| 费用标准 | `data/rules/expense_standards.yaml` | 修改后 `python scripts/seed_data.py`，或在「费用标准」维护 |
| 审批阈值/报销时限 | `data/rules/finance_policy.yaml` | 修改后重启服务 |
| 推荐权重/年级档位 | `data/rules/recommend_weights.yaml` | 修改后重启服务（服务层读取） |
| 获奖积分/工作量 | `data/rules/award_point_rules.yaml` | 修改后 `python scripts/seed_data.py` |
| 赛事认定目录 | `data/rules/competition_category_rules.yaml` | 修改后 `python scripts/seed_data.py` |
| 材料检查量表 | `data/rules/review_rubrics.yaml` | 修改后重启服务 |

具体字段说明见各 YAML 文件头部注释。

## 6. 数据替换检查清单

1. 备份 `backend/data` 与数据库。
2. 用学院真实赛事替换 `competitions.json` 或通过页面维护；确保 `code` 唯一。
3. 用真实台账替换 `ledger.json`；参赛 `code` 唯一，`competition_code` 必须存在。
4. 用真实主数据替换 `master.json`；专业 `code` 被学生引用。
5. 删除或归档演示知识文件，放入学院正式通知/制度；补齐元数据。
6. 执行 `python scripts/seed_data.py` 与 `python scripts/ingest_knowledge.py`。
7. 打开「知识库」确认入库状态与片段数；用检索测试验证关键条款可命中。
8. 打开「统计分析」核对参赛队伍、获奖数、获奖率与学院台账一致。
9. 抽查问答引用、备赛计划、预算/报销规则是否指向新的文件与标准。
10. 在「结果导出」导出三类报表并归档。

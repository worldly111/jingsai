# 部署与使用手册

适用版本：2026-10（交付版）  
适用对象：学院系统管理员、竞赛管理人员、指导教师与学生。

## 1. 运行环境

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11、Ubuntu 20.04+、CentOS 7+ | 已在 Windows 11 + Python 3.13 验证 |
| Python | 3.11 – 3.13 | 需要能创建虚拟环境 |
| 内存 | 建议 4 GB 以上 | 离线向量索引常驻内存约数百 MB |
| 磁盘 | 2 GB 以上 | 依赖、数据库、知识库文件 |
| 浏览器 | Chrome / Edge 最新版 | 页面使用 Vue 3 + ECharts |
| Node.js | 仅前端开发时需要（18+） | 运行期不需要，`frontend/dist` 已构建 |
| 数据库 | SQLite（默认）或 MySQL 8 / PostgreSQL 16 | 通过 `DATABASE_URL` 切换 |
| 大模型 | 可选 | 未配置时自动使用内置离线智能体 |

运行期只需本机可访问，不强制依赖外网。安装 Python 依赖时需要访问 PyPI，可使用国内镜像。

## 2. 安装与启动

### 2.1 一键启动（Windows）

```bat
cd /d <项目目录>
start_windows.bat
```

首次执行会：创建 `backend\.venv` → 安装依赖 → 建库并导入演示数据 → 导入知识库 → 启动服务。之后再次执行会跳过已完成的步骤。

### 2.2 一键启动（Linux / macOS）

```bash
cd <项目目录>
chmod +x start.sh
./start.sh
```

可通过环境变量覆盖监听地址与端口：

```bash
HOST=0.0.0.0 PORT=8080 ./start.sh
```

### 2.3 手动启动（排查问题时推荐）

```bash
cd backend
python -m venv .venv
# Windows
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe scripts\init_db.py --seed
.venv\Scripts\python.exe scripts\ingest_knowledge.py
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# Linux
# .venv/bin/python -m pip install -r requirements.txt
# .venv/bin/python scripts/init_db.py --seed
# .venv/bin/python scripts/ingest_knowledge.py
# .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

访问：

- 系统首页 <http://127.0.0.1:8000>
- OpenAPI 文档 <http://127.0.0.1:8000/api/docs>
- 健康检查 <http://127.0.0.1:8000/api/health>

服务由 FastAPI 同时托管 `/api/*` 与 `frontend/dist` 静态资源，无需单独启动前端。

### 2.4 重新初始化

| 目的 | 操作 |
| --- | --- |
| 重建表但保留文件 | `python scripts/init_db.py --reset`（需输入 `RESET` 确认） |
| 重建并导入演示数据 | `python scripts/init_db.py --reset --seed` |
| 仅重新导入赛事与台账 | `python scripts/seed_data.py` |
| 仅重新导入知识库 | `python scripts/ingest_knowledge.py` |
| 清空后重新导入全部 | 停止服务 → 删除 `backend/data/competition_agent.db` → 重新启动脚本 |

`--reset` 会清空业务单据（预算、借款、报销）与会话日志，请先导出或备份数据库。

## 3. 环境配置

配置文件：`backend/.env`（从 `backend/.env.example` 复制，全部有默认值）。服务需在 `backend` 目录启动，或使用绝对路径指定配置。

### 3.1 基本参数

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `APP_NAME` | 高校学科竞赛辅助服务智能体 | 界面与健康检查显示 |
| `APP_ENV` | development | 环境标识 |
| `HOST` / `PORT` | 127.0.0.1 / 8000 | 监听地址与端口 |
| `CORS_ORIGINS` | * | 允许的跨域来源，生产环境应改为实际域名 |
| `DATABASE_URL` | `sqlite:///./data/competition_agent.db` | 数据库连接串 |
| `SQL_ECHO` | false | 是否输出 SQL 日志 |
| `DEFAULT_COLLEGE` | 计算与智能技术学院 | 默认学院名称 |
| `DATA_DIR` 等 | `./data/*` | 数据、上传、导出、知识库、种子、规则目录 |
| `PROMPT_DIR` | `./prompts` | Prompt 与节点配置目录 |

### 3.2 大模型配置

系统通过 OpenAI 兼容协议调用国产大模型，切换只改环境变量：

```env
LLM_PROVIDER=deepseek
LLM_API_KEY=sk-xxxxxxxx
# 以下留空时使用内置预设
LLM_BASE_URL=
LLM_MODEL=
LLM_TEMPERATURE=0.3
LLM_MAX_TOKENS=2048
LLM_TIMEOUT=120
```

| provider | 默认 Base URL | 默认模型 | 备注 |
| --- | --- | --- | --- |
| `builtin` | — | — | 离线规则引擎，零密钥 |
| `deepseek` | `https://api.deepseek.com/v1` | `deepseek-chat` | 需密钥 |
| `qwen` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 阿里云百炼，需密钥 |
| `doubao` | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-1-5-pro-32k-250115` | 火山方舟，需密钥；模型名以控制台开通的推理接入点为准 |
| `openai_compatible` | 自填 `LLM_BASE_URL` | 自填 `LLM_MODEL` | 任意兼容 `/chat/completions` 的端点 |

说明：

- 未填密钥、端点或模型不完整时，系统自动回退到离线通道，不会导致启动失败。
- 大模型只负责理解与表达；金额、获奖率、排名、时间节点等关键字段仍由规则和结构化数据计算。
- 每次运行结果中的 `mode` 字段会记录实际通道（`offline` 或 provider 名称），可在「智能体工作流」页查看。

#### 3.2.1 通用模型问答（多模型选择）

「通用模型问答」页面对所有身份开放，用户可在页面中切换模型。为各供应商配置独立密钥：

```env
# 可按需配置多家；未配置的模型会在页面中显示为“未配置”并禁用
DEEPSEEK_API_KEY=
QWEN_API_KEY=
DOUBAO_API_KEY=
# 可选：覆盖默认模型名
DEEPSEEK_MODEL=
QWEN_MODEL=
DOUBAO_MODEL=
# 通用问答上下文上限
LLM_CHAT_MAX_MESSAGES=20
LLM_CHAT_MAX_CHARS=16000
```

- 当前主通道（`LLM_PROVIDER` 对应供应商）可复用 `LLM_API_KEY`；其他供应商使用各自的 `*_API_KEY`，不会把一家的密钥发送到另一家端点。
- 只配置通用问答密钥、保持业务智能体离线：将 `LLM_PROVIDER` 保持为 `builtin`，仅填写上述供应商密钥即可。
- 自定义/本地端点：设置 `LLM_PROVIDER=openai_compatible`、`LLM_BASE_URL`、`LLM_MODEL`；本地端点可不填 `LLM_API_KEY`。
- 通用问答不检索知识库、不读取台账，回答不作为业务事实依据；密钥只在后端读取，`GET /api/llm/models` 不返回密钥或端点地址。

### 3.3 向量模型配置

```env
EMBEDDING_PROVIDER=builtin   # builtin / qwen / doubao
EMBEDDING_API_KEY=           # 留空时复用 LLM_API_KEY
EMBEDDING_BASE_URL=
EMBEDDING_MODEL=
EMBEDDING_DIM=512
```

| provider | 默认模型 | 维度 |
| --- | --- | --- |
| `builtin` | 离线哈希向量（字符 n-gram TF-IDF） | 512 |
| `qwen` | `text-embedding-v3` | 1024 |
| `doubao` | `doubao-embedding-text-240715` | 2560 |

切换向量模型后必须重建索引，否则新旧向量维度不一致：

```bash
python scripts/ingest_knowledge.py
```

或在「知识库」页面点击「同步目录」/单文档「重建」。

### 3.4 RAG 检索参数

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `RAG_CHUNK_SIZE` / `RAG_CHUNK_OVERLAP` | 600 / 100 | 分块长度与重叠字符数 |
| `RAG_TOP_K` | 6 | 最终返回片段数 |
| `RAG_RECALL_K` | 20 | 召回候选数 |
| `RAG_VECTOR_WEIGHT` / `RAG_KEYWORD_WEIGHT` | 0.6 / 0.4 | 向量与关键词权重，自动归一化 |
| `RAG_MIN_SCORE` | 0.05 | 最低相关度阈值 |

### 3.5 切换 MySQL / PostgreSQL

1. 创建数据库（字符集 `utf8mb4`）。
2. 修改 `backend/.env`：

```env
DATABASE_URL=mysql+pymysql://user:password@127.0.0.1:3306/competition_agent?charset=utf8mb4
```

或：

```env
DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/competition_agent
```

3. 初始化并导入：

```bash
python scripts/init_db.py --seed
python scripts/ingest_knowledge.py
```

4. 重启服务。数据库驱动已包含在 `requirements.txt`（PyMySQL、psycopg[binary]）。数据模型使用标准 SQLAlchemy 2.0 类型，无 SQLite 专有语法；切换后业务功能一致。

## 4. 页面使用说明

导航顺序与实际工作流一致：工作台 → 知识问答 → 通用模型问答 → 推荐 → 备赛 → 项目指导 → 经费辅助 → 赛事台账 → 参赛与获奖台账 → 统计分析 → 知识库 → 结果导出 → 智能体工作流。导航项按当前身份过滤，学生看不到经费、台账、知识库、导出与工作流入口。

### 4.1 工作台

- 展示平台状态、运行通道、知识库规模、台账规模、智能体校验结果。
- 关键指标：在库赛事、参赛队伍、获奖记录、知识文件、智能体调用、问答引用率。
- 「参赛与获奖趋势」图表、未来 180 天赛事节点、智能体入口、最近运行、经费概览。
- 学生仅显示 5 个通用智能体入口与公开指标；教师/管理员额外显示运行日志、引用率与经费概览，管理员可见全部 8 个智能体。
- 顶部「向知识库提问」「为我匹配赛事」可直达对应页面。

### 4.2 竞赛知识问答

1. 在输入框描述问题，例如「2026 年蓝桥杯的报名截止时间和参赛对象是什么？」。
2. 当前身份由页面右上角选择器决定；系统以该身份检索知识库并结合赛事台账回答。
3. 回答下方「参考资料」列出原文标题、文号、章节位置、相关度与原文下载按钮。
4. 右侧显示结构化结果（时间节点、奖项设置、历年数据）与「原文依据与溯源」卡片。
5. 「执行过程」可展开查看 5–6 个节点的耗时与说明；底部可导出 Word / Markdown。
6. 会话自动保存，并按身份隔离；切换身份后会清空当前对话并只加载该身份的会话。管理员可查看全部会话。

回答规则：知识库没有依据时会明确说明「未收录」，并提示需要补充哪类文件，不编造政策条款。

### 4.3 通用模型问答

面向全部身份（学生、教师、管理员）的通用大模型对话窗口，与 8 个业务智能体相互独立。

1. 左侧「选择模型」列出后端登记的全部模型（DeepSeek、通义千问、豆包，以及可选的自定义 OpenAI 兼容端点）。未配置密钥的模型显示「未配置」并禁用；右上角刷新按钮可重新检测状态。
2. 只可选择后端已登记的模型；页面不提交端点或密钥，密钥始终只在服务端读取。选中的模型保存在浏览器 `localStorage` 的 `ci.chatModel`，下次打开自动恢复。
3. 输入问题后按 Enter 发送、Shift + Enter 换行；支持多轮上下文，单条最多 4000 字。页面发送前按 20 条消息、累计 16000 字符从最早的消息开始截断；服务端对超出上限的请求分别返回 400 / 413。
4. 回答以 Markdown 渲染，标注供应商、模型名、耗时与 token 用量，可复制；调用失败会在对话中显示具体原因（未配置、鉴权失败、额度不足、超时等）。
5. 对话只保留在当前页面，刷新或「清空对话」后丢弃，不写入数据库，也不参与问答会话隔离与归档。
6. 页面顶部与模型面板明确提示：本页不检索知识库、不读取台账、不生成引用，回答不作为竞赛政策、费用或统计的事实依据；这类问题应使用「竞赛知识问答」或对应业务页面。

无可用模型时，页面显示「0 个可用 / N 个已登记」、配置指引与所需环境变量，发送按钮保持禁用。配置方式见 3.2.1 节。

### 4.4 竞赛推荐

1. 填写专业、年级、技术方向标签、项目基础、意向级别；也可直接用自然语言描述。
2. 系统按专业适配、技术方向、年级、项目情况、赛事级别、报名时效计算适配度。
3. 输出推荐清单（适配度、难度、报名截止、报名费）、推荐理由、学院历年参赛与获奖数据。
4. 「下一步动作」可直接跳转备赛或预算。

推荐权重与赛事适配数据均可维护：`data/rules/recommend_weights.yaml` 与 `major_competition_fit` 表。

### 4.5 备赛辅助

1. 选择赛事与届次（或输入赛事名），可指定目标日期（默认取报名截止日）。
2. 系统基于报名截止与比赛时间倒排阶段，生成任务清单、交付物与材料准备要求。
3. 同时检索该赛事规程中的材料格式与提交要求，附引用。
4. 导出 Word / Markdown 作为备赛计划下发。

若所选届次报名已截止，系统会明确提示，并保留该届材料要求作为下一届参考。

### 4.6 项目指导辅助

1. 粘贴项目申报书/作品说明正文，或上传 PDF/Word 由系统抽取文本。
2. 选择材料类型（申报书、商业计划书、作品说明、答辩稿等），可关联赛事。
3. 输出初检评分、必须修改/建议修改/可选优化项、章节完整性核对表、材料亮点与预答辩问题。
4. 配置大模型后还会生成改写建议与示例；离线模式使用量表内置建议。

检查量表位于 `data/rules/review_rubrics.yaml`，可新增材料类型或调整字数、关键词与问题模板。

### 4.7 经费辅助

页面包含四个页签：

| 页签 | 操作 |
| --- | --- |
| 预算申请 | 选择赛事、填写人数/地点/天数/交通方式，测算明细并生成预算申请；保存后可提交审批 |
| 借款 | 选择已批准预算，填写借款人、金额、预计冲销日期；生成借款单并执行校验 |
| 报销 | 关联预算与借款，逐项录入支出、发票号、日期；系统检查缺票、超标、超预算、时限 |
| 费用标准 | 查看当前费用标准与依据 |

单据状态流转：

- 预算：草稿 → 待审批 → 已批准 / 已驳回。
- 借款：草稿 → 待审批 → 已借出 → 已冲销。
- 报销：草稿 → 待审核 → 已通过 / 已驳回。报销通过时，若关联借款未冲销，系统自动将其置为「已冲销」。

每张单据均可导出 Word（申请/借款/报销单）或 Excel 明细。参考列表会在切换页签与保存后自动刷新。

权限：学生无法进入该页；教师在预算/借款/报销中可保存草稿、提交审批、查看与导出单据，但「批准 / 驳回 / 放款 / 冲销」按钮仅管理员可见，接口层同样拒绝教师的审批状态变更。

### 4.8 赛事台账

- 查看 12 项赛事及其级别、类别、主办单位、最近年度、报名窗口、参赛规模。
- 支持按关键词、级别、年度筛选；展开详情可查看届次、赛道、时间节点、奖项设置与学院获奖记录。
- 管理员可新增赛事、编辑赛事、新增/编辑届次（年度、通知、报名时间、资格、组队、费用、材料）；学生与教师为只读。
- 右侧「学院参赛与获奖」显示该赛事的历年台账摘要。

### 4.9 参赛与获奖台账

- 仅教师与管理员可访问；学生导航中不显示，直接访问路由会回到工作台。
- 80 条参赛记录，可展开查看队员与指导教师、获奖明细。
- 支持年度、赛事、级别、专业、状态、关键词筛选与分页。
- 顶部汇总：参赛队伍、参赛人次、获奖数量、涉及学生/教师。
- 支持导出 Excel 台账（按当前筛选条件）。

### 4.10 统计分析

- 8 个统计维度：年度、赛事、专业、获奖等级、赛事级别、教师、学生、教师工作量。
- 顶部总览指标、8 张 ECharts 图表（趋势、对比、占比、热力图等）、明细表。
- 「智能体分析」可让统计智能体按当前筛选生成结论、表格与图表，并展示逐节点轨迹。
- 所有统计均来自 `registrations` / `awards` / `registration_members` 等结构化表，按队长专业归集专业维度，获奖率 = 获奖数 / 参赛队数。
- 三种身份均可查看统计；批量报表导出按钮仅教师与管理员可见。

### 4.11 知识库

- 仅教师与管理员可进入；教师为只读，可检索、查看详情与下载原文。
- 顶部：文档数、片段数、索引状态、入库异常数、文档类型分布、支持格式。
- 「知识检索测试」：输入问题直接查看混合检索结果、章节位置、相关度与原文下载，不调用大模型。
- 「文档目录」：按标题、类型、年度筛选；每份文档可查看详情、下载原文。
- 管理员额外具备「上传文档」「同步目录」「重建索引」「删除」能力：上传支持 PDF/Word/Excel/Markdown/TXT/CSV/JSON，填写类型、年度、关联赛事、发文单位、文号、链接、标签后解析入库；同步目录扫描 `backend/data/knowledge` 增量导入。

### 4.12 结果导出

- 仅教师与管理员可进入导出中心；学生导航中不显示，但可在各智能体结果卡片上导出当次结果（`export.result`）。
- 报表范围：年度、赛事、级别、专业、关键词，决定统计与台账导出的筛选条件。
- 6 类结构化报表：统计工作簿（多工作表）、获奖明细、参赛台账、知识文档清单、费用标准、积分与工作量规则。
- 知识问答会话归档：选择会话后导出完整问答与引用（Word / Markdown）；会话列表按身份隔离。
- 归档统计：智能体运行记录、问答记录、引用覆盖率。

### 4.13 智能体工作流

- 仅管理员可访问。
- 查看 8 个智能体的节点、边、条件路由、回答规则与运行通道。
- 「校验配置」检查 `prompts/*.yaml` 与代码图结构是否一致。
- 「在线测试台」选择智能体、填写问题与 JSON 参数直接运行，查看回答、结构化结果、图表、校验项、引用与逐节点轨迹。
- 最近运行记录包含 Run ID、状态、耗时、输出摘要与时间。

## 5. 运维与故障排查

| 现象 | 排查与处理 |
| --- | --- |
| 端口被占用 | `netstat -ano | findstr :8000`（Windows）或 `lsof -i:8000`；停止占用进程或改 `PORT` |
| 页面 404（刷新子路由） | 确认访问的是 FastAPI 服务端口而非 Vite 端口；`frontend/dist` 必须存在 |
| 前端样式/脚本未更新 | 重新执行 `npm run build`，浏览器强制刷新 |
| 修改后端代码未生效 | 默认未开启 `--reload`，重启 uvicorn |
| 知识库检索为空 | 查看「知识库」页入库异常；执行 `scripts/ingest_knowledge.py`；确认 `EMBEDDING_DIM` 与模型一致 |
| 切换向量模型后报维度错误 | 重新导入/重建全部知识文档索引 |
| 大模型未生效 | 查看 `/api/health` 的 `runtime` 与「工作流」页运行通道；确认密钥、Base URL、模型名；失败会自动回退离线 |
| 通用模型问答显示「暂无可用模型」 | 在 `backend/.env` 配置 `DEEPSEEK_API_KEY` / `QWEN_API_KEY` / `DOUBAO_API_KEY`，或配置自定义端点，重启服务后点右侧刷新；业务智能体保持 `LLM_PROVIDER=builtin` 不影响本页 |
| 通用问答返回 502，提示「鉴权失败」 | 对应供应商密钥无效或无权限；确认密钥与供应商匹配，不要把 A 平台的密钥填到 B 平台的变量 |
| 通用问答返回 502，提示「请求频率或额度受限」 | 供应商额度或频率受限；检查账户余额与限流，稍后重试 |
| 通用问答返回 504 | 供应商响应超时；检查网络与端点，稍后重试或换用其他已配置模型 |
| 数据库切换后无数据 | 执行 `init_db.py --seed` 与 `ingest_knowledge.py` |
| 上传文档失败 | 检查格式（pdf/docx/xlsx/md/txt/csv/json 等）、单文件 ≤ 50 MB、是否扫描版 PDF（无文本层） |
| 报销单无法关联借款 | 借款需先存在且未冲销；选择预算后列表按赛事过滤；保存后会自动刷新 |
| 导出 Word 失败 | 检查单据是否存在、`python-docx` 是否安装；后端日志会给出具体异常 |

日志：uvicorn 标准输出；业务侧可在「智能体工作流」查看运行记录，数据库表 `agent_run_logs`、`qa_logs` 保留输入摘要、节点轨迹与耗时。

## 6. 角色权限与安全

系统在应用层实现学生 / 教师 / 管理员三种身份的权限分离。页面右上角（移动端在侧边菜单底部）提供演示身份选择器；切换后导航、路由、操作按钮与接口权限同步变化。

### 6.1 权限矩阵

| 权限 | 学生 | 教师 | 管理员 |
| --- | :---: | :---: | :---: |
| 工作台、知识问答、推荐、备赛、项目指导 | ✓ | ✓ | ✓ |
| 通用模型问答（可使用已配置模型） | ✓ | ✓ | ✓ |
| 统计分析、赛事台账查看 | ✓ | ✓ | ✓ |
| 单次智能体结果导出 | ✓ | ✓ | ✓ |
| 参赛与获奖台账、批量报表导出、运行日志 | — | ✓ | ✓ |
| 经费编制、提交与单据下载 | — | ✓ | ✓ |
| 经费批准、驳回、放款、冲销 | — | — | ✓ |
| 知识库查看 | — | ✓ | ✓ |
| 知识库上传、同步、重建、删除 | — | — | ✓ |
| 赛事新增、年度收录、编辑 | — | — | ✓ |
| 智能体工作流总览与在线测试台 | — | — | ✓ |

### 6.2 接口约定

- 所有请求携带请求头 `X-User-Role`，取值为 ASCII 标识 `student` / `teacher` / `admin`；HTTP 头不应直接使用中文角色名。
- 未知身份返回 `400`；权限不足返回 `403`；前端会把后端 `detail` 直接展示给用户。
- `GET /api/meta/permissions` 返回当前身份与权限清单；`GET /api/meta/agents` 仅返回当前身份可用智能体（学生 5 个、教师 8 个、管理员 8 个）。
- 角色以请求头为准，后端会覆盖请求体中的 `user_role`，客户端不能通过改请求体提权。
- 问答会话记录所属身份：学生与教师只能读取/删除自己的会话，管理员可读取全部会话；跨身份访问返回 `403`。
- 经费审批状态变更（已批准、已驳回、已借出、已冲销、已通过）仅管理员可执行；教师限于草稿与待审批/待审核。
- 通用问答接口（`/api/llm/*`）要求 `llm.use`，三种身份均具备；接口只接受服务端登记过的 `model` 标识，不接受调用方提交 `base_url` 或密钥。
- `GET /api/llm/models` 返回模型清单、可用状态、默认模型、上下文上限与免责声明，不返回任何密钥或端点地址。
- `POST /api/llm/chat` 请求体为 `{model, messages, temperature?, max_tokens?}`；`messages` 仅允许 `user` / `assistant`，最后一条必须为 `user`。未知模型返回 `400`，模型未配置返回 `503`，超过消息数或字符上限返回 `400` / `413`；供应商 HTTP 错误统一返回 `502`（鉴权失败、额度受限等在 `detail` 中说明），超时返回 `504`。
- 通用问答不写 `chat_messages`、`qa_logs` 或 `agent_run_logs`，不参与会话隔离；系统提示词固定由后端注入，客户端不能覆盖。

### 6.3 前端行为

- `frontend/src/auth.js` 维护与后端一致的权限矩阵，`X-User-Role` 映射为 `student|teacher|admin`。
- 路由 `meta.permission` + 全局守卫阻止越权页面；直接访问受限 URL 会回到工作台。
- 导航分组、审批按钮、知识库写操作、批量导出等均通过 `can(permission)` 渲染。
- 演示身份保存在浏览器 `localStorage` 的 `ci.role`，无后端账号状态。
- 通用问答当前选择的模型保存在 `localStorage` 的 `ci.chatModel`，仅作为体验偏好；若该模型不再可用，回退到第一个可用模型。对话内容不做本地持久化。

### 6.4 正式接入统一身份认证

当前实现是**应用级角色控制，不是身份认证**。上线时应：

1. 在学校统一身份认证（CAS / OAuth2 / 反向代理网关）完成登录校验。
2. 由认证层根据账号属性映射角色并注入可信的 `X-User-Role`，同时**剥离客户端传入的同名请求头**，防止伪造。
3. 移除前端演示身份选择器，角色只读展示。
4. 对经费审批、知识库写入等高风险接口增加操作审计；必要时为管理员接口增加二次校验或 IP 白名单。

## 7. 生产部署建议

1. **进程**：使用 `uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 2` 或 systemd/supervisor 托管；SQLite 场景建议单 worker，避免并发写入争用。
2. **反向代理**：Nginx 将 80/443 转发到 8000，开启 gzip 与静态缓存；上传大小限制至少 50 MB。
3. **身份认证**：按第 6.4 节接入学校统一身份认证，由认证层注入角色请求头并移除前端角色切换，不能用客户端可自由修改的角色头直接暴露到公网。
4. **数据备份**：定期备份 `backend/data/competition_agent.db`（或 MySQL/PostgreSQL 数据库）与 `backend/data/knowledge`、`backend/data/seed`、`backend/data/rules`。
5. **密钥管理**：`.env` 不纳入版本库；仅授予服务账号读取权限。不要把 API Key 写入前端或导出文件。通用问答的供应商密钥同样只放在后端，禁止通过反向代理把密钥注入到前端环境变量。
6. **通用问答治理**：通用问答直接调用外部供应商，内容不经过知识库与业务审核。上线前应明确使用范围与数据合规要求，禁止输入敏感个人信息、未公开材料与账号口令；建议在网关或应用层增加按身份/账号的频率与额度限制、并发上限和调用审计，并为供应商设置独立预算与告警。若学校不允许直连公网模型，可只配置校内 `openai_compatible` 端点或不配置任何密钥，本页会保持禁用，不影响业务功能。
7. **CORS**：生产环境将 `CORS_ORIGINS` 设置为实际域名，不使用 `*`。
8. **升级**：保留 `data` 目录与 `.env`，替换代码后执行 `pip install -r requirements.txt`、`init_db.py`（补建新表）、重启；数据结构采用增量建表，不会主动删除已有表。

## 8. 最小验收路径

1. 启动服务，打开工作台，确认状态为「运行中」。
2. 知识问答提问「2026 年蓝桥杯的报名截止时间和参赛对象是什么？」，确认回答带 `[^n]` 引用与原文下载。
3. 竞赛推荐填写「软件工程 / 大二 / Python、数据分析 / 有项目」，确认返回 6 项排序结果。
4. 备赛辅助选择蓝桥杯，确认生成阶段计划与材料清单。
5. 项目指导粘贴申报书片段，确认评分、缺失章节与答辩问题。
6. 经费辅助依次生成预算、借款、报销，确认金额大写、校验项与 Word 导出。
7. 统计分析查看 8 个图表与 8 个维度，确认数字与台账一致。
8. 结果导出下载统计工作簿、获奖明细、参赛台账，确认文件可打开。
9. 通用模型问答：以学生身份打开页面，确认可进入；有已配置模型时可切换并完成一轮对话，回答显示供应商、模型与耗时；无可用模型时显示配置指引且发送按钮禁用；确认页面提示「不作为业务依据」并可跳转竞赛知识问答。
10. 「智能体工作流」校验配置并运行一个智能体，确认节点轨迹完整。

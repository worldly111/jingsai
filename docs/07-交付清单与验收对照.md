## 5. 可迁移性与维护说明

### 5.1 迁移到另一台服务器

1. 复制整个项目目录（含 `backend/data/`、`frontend/dist/`、`backend/prompts/`）；
2. 安装 Python 3.11–3.13，创建虚拟环境并安装 `backend/requirements.txt`；
3. 如需沿用演示数据，保留 `backend/data/competition_agent.db`；如需重建，执行 `init_db.py --seed` 与 `ingest_knowledge.py`；
4. 按需复制 `backend/.env.example` 为 `.env`，配置大模型/向量模型与数据库；
5. 运行 `start_windows.bat` 或 `start.sh`，访问 8000 端口；
6. 生产环境在 Nginx/网关层配置 HTTPS、统一身份认证、访问控制与 `CORS_ORIGINS`。

### 5.2 切换数据库

```env
# MySQL 8
DATABASE_URL=mysql+pymysql://user:password@127.0.0.1:3306/competition_agent?charset=utf8mb4

# PostgreSQL 16
DATABASE_URL=postgresql+psycopg://user:password@127.0.0.1:5432/competition_agent
```

切换后重新执行建库、种子导入与知识库导入；建议先在测试库完成一轮冒烟与统计核对。

### 5.3 日常维护

| 任务 | 操作 | 频率 |
| --- | --- | --- |
| 新增赛事/届次 | 赛事台账页面维护，或更新种子 JSON | 每学期/每年 |
| 新增年度参赛与获奖 | 台账页面录入或批量导入 | 成绩公布后 15 个工作日内 |
| 替换政策文件 | 知识库上传新文件，归档旧文件，重建索引 | 通知发布时 |
| 调整费用/积分规则 | 修改 YAML 并重新导入，核对预算与统计 | 制度修订时 |
| 调整回答风格 | 修改对应 Prompt YAML，运行 `smoke_agents.py` | 按需 |
| 配置通用问答模型 | 修改 `backend/.env` 中的 `*_API_KEY` / `*_MODEL`，重启后在页面刷新模型状态 | 按需 |
| 备份 | 备份数据库文件/数据库实例与 `data/knowledge/` | 每周/每次批量导入前 |

## 7. 已知边界与交付后建议

| 事项 | 说明 | 建议 |
| --- | --- | --- |
| 演示数据 | 赛事时间、费用、获奖记录为演示口径 | 上线前按学院当年通知和真实台账替换 |
| 登录鉴权 | 已实现应用级角色权限，但角色请求头由前端携带，不含登录认证 | 部署时在反向代理/网关接入统一身份认证，注入可信角色并剥离客户端同名请求头，移除演示身份选择器；收紧 `CORS_ORIGINS` |
| 大模型通道 | 默认离线；三家 API 适配代码已提供但未用真实密钥联调 | 配置密钥后执行问答/推荐/预算用例，核对引用与金额不变 |
| 通用模型问答 | 面向全部身份的通用对话，不检索知识库、不读取台账、不生成引用；本次仅用本地模拟端点验证协议，未使用真实供应商密钥 | 上线前配置至少一家密钥做真实联调；明确其非权威边界；增加按账号的频率/额度限制与调用审计，禁止输入敏感信息 |
| MySQL/PostgreSQL | 代码支持，但本次交付测试使用 SQLite | 切换后执行建库、导入与冒烟，确认分页/排序/日期类型 |
